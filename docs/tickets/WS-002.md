# WS-002: Fix subclass feature loading

## Description

Subclass features fail to load for 8/12 subclasses (G5 from UX Review 2). Working: Evoker, Thief, Champion, Gloom Stalker. Failing: Disciple of Life, Circle Forms, and others. Root cause: PocketBase query failures — console errors on certain feature names. Likely a query escaping or name matching issue.

## Acceptance Criteria

- [x] All 12+ PHB subclasses load their features correctly
- [x] Subclass features display in the character sheet features section
- [x] No console errors when selecting any subclass
- [x] 2024 (XPHB) subclasses also load correctly

## Activity Log

- **2026-03-19:** Investigated subclass feature loading across codebase. Found primary bug in `src/utils/character-builder.ts`: `buildCharacter()` saved `subclass.name` (full name like "Life Domain", "Path of the Giant") instead of `subclass.shortName` (like "Life", "Giant") to `character.classes[].subclassName`. The `class_features` PB collection stores `subclassName` as the short form, so queries like `subclassName="Life Domain"` returned zero results. Working subclasses (Evoker, Thief, Champion, Gloom Stalker) happened to have `name == shortName`.
- **2026-03-19:** Also fixed missing PB filter escaping in `src/api/classes.ts` (`getSubclasses`) and `src/components/create/RefEntry.tsx` (`parseRefKey`) — double quotes in values could break filter syntax. The `useCharacterSheet.ts` path already used `sc.shortName` correctly.
- **2026-03-19:** Type-check passed. Three files changed: `character-builder.ts`, `classes.ts`, `RefEntry.tsx`.

## Notes

Reference: `review/UX-REVIEW-2.md`, gap G5. Check PB query construction — likely special characters in feature names breaking the filter.

**Note:** Existing characters created before this fix have the full subclass name stored. They will need their `subclassName` field updated to the short form. This is a data concern, not a code concern.

## Resolution

**Root cause:** `character-builder.ts` saved `subclass.name` (full name) instead of `subclass.shortName` to the character's `subclassName` field. The `fetchSubclassFeatures()` query in `api/wiki.ts` matches against `class_features.subclassName`, which stores the short form. This caused a mismatch for any subclass where `name != shortName` (8 of 12 PHB subclasses).

**Fix:** Changed `character-builder.ts:65` from `subclass?.name` to `subclass?.shortName`. Added filter value escaping in `classes.ts` and `RefEntry.tsx` as a defensive measure.
